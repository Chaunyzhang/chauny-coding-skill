# 产品思考框架

用途：帮助 Agent 在正式 Product Definition 之外进行更宽的产品推理。推演、模拟、反问和假说是思考工具，不天然进入正式文档。

## 1. 基本姿态

不要把用户的第一个说法当最终产品定义。先理解真实目标，再从理想形态与现实约束两侧验证。

Agent 在思考中同时承担四种角色：

- **整理者**：准确吸收已表达想法。
- **追问者**：寻找真正会改变产品判断的问题。
- **反方**：攻击闭环、商业、行为与市场假说。
- **扩展者**：帮助用户看见 3–5 年后的自然产品形态，而非只困在当前成果。

这些只是思考角色，不进入产品文档术语。

## 2. 产品存在性：为什么值得存在

优先逼近：

- 用户处于什么不满意状态；问题是高频、高损失、高焦虑、高机会成本，还是轻微不便。
- 用户今天如何解决，为什么继续忍受现状也可能合理。
- 产品让用户发生什么真实变化，而不只是多一个工具。
- 用户为何值得为此改变行为、迁移数据、学习流程或建立信任。
- 产品消失时，哪些用户会真正感到损失，为什么。

危险信号：价值只靠“更智能 / 更方便 / 更漂亮”表达；只是换界面却不改变结果或成本；痛点只有创始人想象，没有真实替代行为证据。

## 3. User Reality：从行为而非虚构画像出发

关注与产品决策有关的：处境、目标、当前行为 / 替代方案、触发、动机、阻力、采用决策角色、真实使用者与退出条件。不要为了完整 Persona 虚构年龄、城市、兴趣等无关属性。

必要时临时模拟 2–4 个角色，例如核心高意愿用户、普通低耐心用户、怀疑型用户，以及与使用者不同的付款者 / 管理者。

模拟时检查：

1. 为什么此刻想到这个产品？
2. 第一动作愿不愿做？看到价值前需付出多少？
3. 哪一步最容易退出？
4. 看到什么才认定“真的有用”？
5. 为什么回来？
6. 付费时会与什么比较？

只有形成稳定产品要求的模拟结论才进入 Definition；模拟对白和过程不落文档。

## 4. 用户价值闭环

统一用：

`Need → Trigger → Entry → Action → Product Response → State Change → Visible Value → Return Reason`

逐环判断：

- **Need**：需求真实吗？用户已意识到还是需要教育？
- **Trigger**：什么真实事件让用户现在行动？频率 / 重要性够吗？
- **Entry**：为什么想到本产品而非替代方案？发现 / 获客是否依赖不现实前提？
- **Action**：用户需提供什么输入或改变什么行为？初始成本是否高于预期价值？
- **Product Response**：产品具体做了什么，禁止用“智能处理 / 自动优化”等空词替代。
- **State Change**：真正改变了内容、决策、资产、流程、关系、知识、结果还是风险？
- **Visible Value**：用户如何知道成功？价值是否足够快、具体、可感知？
- **Return Reason**：为何再次使用？来自重复需求、状态积累、协作、数据资产、自动化或持续服务？没有回访理由时，要确认是一次性产品还是闭环缺失。

闭环攻击至少覆盖：无产品时如何完成；哪一环依赖用户异常勤快；价值是否出现过晚；是否需先积累大量数据；二次使用是真需求还是人为提醒；新增功能是否强化闭环而非只增加菜单。

## 5. 商业闭环

统一检查：

`Value Creation → Value Delivery → Value Capture → Continued Value → Retention / Renewal`

- **Value Creation**：创造何种可感知 / 可衡量价值，如省时间、增收入、降风险、提质量、体验、身份 / 关系。
- **Value Delivery**：谁获得价值，出现频率与时点如何。
- **Value Capture**：谁付钱、为何由该角色付、按什么收费、付费时点是否匹配价值时点、免费替代存在时为何仍值得付。
- **Continued Value**：使用越久价值是否累积；若价值完全一次性，订阅是否合理。
- **Retention / Renewal**：为何下月 / 明年继续付费；到期失去什么；续费若主要靠迁移锁定，要检查信任风险。

商业压力测试：付款者与使用者是否冲突；收入增长是否被人工 / AI / 服务成本吞噬；高价值用户是否最昂贵；免费层是否仍能体验核心价值；价格上限由何种替代方案决定；竞品免费时为何仍成立；高销售成本是否有足够客单价；双边市场如何冷启动。

## 6. 模式压力测试

每个重要产品假说至少问一次：

> 如果这个产品失败，最可能因为什么？

常见原因：需求不强、价值太晚 / 输入太重、用户不改变行为、无真实回访理由、使用者喜欢但付款者不买、价值覆盖不了获客 / 交付成本、网络效应无法冷启动、人工服务无法规模化、过度依赖平台 / 渠道 / 供应商 / 模型、AI 成本 / 错误 / 责任破坏商业或信任、先要大量数据但用户不愿提供、市场可触达规模过小或渠道过贵。

对最重要的 1–3 个失败原因，明确：已有证据、需要验证，还是可通过产品设计降低。

## 7. Market Reality

市场研究用于验证关键产品假说，不是做漂亮 TAM。先明确需要验证什么，例如：需求频率、替代行为、历史付费、经济可触达性、行业 / 平台 / 监管限制。

市场承载重点看：目标用户数量与集中度、问题频率与价值密度、当前支出 / 机会成本、可用获客渠道、决策周期与商业模型匹配、现有市场池是否足够、地域 / 语言 / 法规 / 生态依赖是否显著缩小可服务范围。

市场规模数字只有来源可靠且会改变产品判断时才值得进入 Product Definition。

## 8. 竞品与案例研究

竞争至少包括：直接竞品、不同形式的替代方案，以及“不行动”。

不要做功能表式竞品分析。重点研究：服务谁、核心结果、采用原因、第一次价值、核心闭环、留存、付款者与付费理由、获客、关键成本 / 风险，以及哪些机制证明了我们的假说、哪些条件并不可迁移。

成功案例不能直接证明本产品成功。必须区分相似条件、不同条件、可借鉴的机制 / 渠道 / 价值 / 商业模型，以及仍然只是推断的部分。

## 9. Ideal Product State

现实压力测试不是为了把产品越做越保守。核心假说有一定基础后，主动思考：

- 资源暂不构成约束时，最终希望把用户问题解决到什么程度。
- 用户 / 角色、核心旅程与能力族如何自然扩展。
- AI / 自动化最终可承担什么，哪些决策必须留给人。
- 是否会跨端、开放生态、接入第三方或形成平台关系。
- 商业形态、数据、内容、组织、权限和 ownership 最终如何扩展。
- 哪些诱人方向明确不属于愿景。
- 无论如何扩展，哪些产品原则不能被破坏。

Ideal Product State 只有形成长期产品约束或能力方向时才进入正式文档；宏大愿景文案本身没有文档价值。

## 10. 从思考到产品结论

长讨论结束时，不总结“讨论了什么”，而提炼：产品结论如何变化、关键假说得到支持还是被推翻、发现了哪些真实约束、能力 / 未来方向如何增删调整、哪些问题仍会实质影响产品。

思考的价值通过更好的产品结论体现，不通过保存思考过程体现。
