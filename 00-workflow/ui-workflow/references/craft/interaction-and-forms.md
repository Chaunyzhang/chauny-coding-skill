# 交互防错、弹层分工与表单人因

设计交互闭环、弹窗抽屉、导航菜单、按钮权责与表单录入时读。跨平台通用，不绑定具体框架。

## 目录

- 1. 交互闭环与副作用锁定
- 2. 可逆性、高危防错与按钮权责（必须）
- 3. 四类承载容器分工与禁叠窗（必须）
- 4. 示能诚实、感知稳定性与直接操作（必须）
- 5. 控件与选项量级选型（必须）
- 6. 表单与输入人因铁律（必须）
- 7. 可访问性横切底线（必须）

## 1. 交互闭环与副作用锁定

- 重要动作必须完整定义闭环：`affordance → event → intent → precondition → command → immediate response → pending → success/failure → recovery`，不能只写“点击完成任务”。
- 触发副作用的交互控件（提交、支付、删除、发送）必须显式定义 `loading`（含防重入锁定，避免双击重复提交）与键盘 `focus-visible`。

## 2. 可逆性、高危防错与按钮权责（必须）

- **可逆操作优先 Undo，不可逆高危才弹窗**：能撤回的动作（归档、移除列表项、状态切换）直接执行并给右下角带「撤销」按钮的 Toast，减少打断；真正不可逆或高影响动作（永久删除、清空、扣费、权限重置）必须弹确认框写清受影响对象与后果。
- **拒绝万能「确定 / 取消」**：确认框的操作按钮必须用明确动宾文案点出真实后果（例如「删除 3 个文件 / 保留」），不能写空洞的「确定 / 取消」「是 / 否」（用户在惯性点击下根本不读正文，动宾文案是最后一道防错闸）。
- **高危焦点落安全项 & 物理隔离**：破坏性确认框打开时，默认键盘焦点必须落在「取消/保留」而非「删除」上，防止用户误敲回车直接删除；工作区内的「删除/重置/清空」按钮不能紧贴「保存/提交」主按钮并排同权重摆放，必须拉开距离、视觉降级或收进更多菜单。
- **同一独立操作区最多 1 个主强调按钮**：页头、工具栏、表单底栏、弹窗底栏最多只允许 1 个实心主按钮，避免用户同时面对多个强焦点犹豫误点。

## 3. 四类承载容器分工与禁叠窗（必须）

按“是否阻断底层”与“是否保留上下文”严格区分四类容器，禁止混用：
- **Inspector（侧边常驻属性栏）**：跟随主画布选中对象实时联动，非模态、可随时开关、绝不遮挡画布。
- **Popover（锚定气泡）**：紧贴触发元素弹出，承载少量次级控件或摘要，点外部即关；**同一时刻全屏最多存在 1 个 Popover，严禁气泡里再弹气泡**。
- **Sheet / Drawer（窗口内嵌层 / 侧边抽屉）**：用于自包含任务或需要对照底层上下文的多字段编辑；桌面多窗下 Sheet 只锁当前所属文档/窗口，不锁死其他窗口。
- **Modal / Alert（居中模态 / 高危警报）**：仅用于高危确认、短聚焦录入（通常 < 5 项）或紧急阻断；不能拿 Alert 展示普通信息。
- **严禁弹窗叠弹窗（No Modal-on-Modal）**：不能在已打开的 Modal 上再弹第二个 Modal（次级流程改在当前容器内步进切换或替换内容，防止焦点击穿与空间迷失）。
- **遮罩关闭分级**：纯浏览/只读弹层允许点遮罩或按 `Esc` 立即关闭；**含未保存录入内容的弹窗或抽屉，严禁点击遮罩静默关闭丢失数据**，必须拦截并提示确认离开。

## 4. 示能诚实、感知稳定性与直接操作（必须）

- **示能诚实（不伪装、不隐身）**：不可点击的静态标签或状态块不能长得像按钮误导点击；核心操作不能只靠 `:hover` 才露出（触屏无法悬停、键盘难以发现）；主导航不能用无文字的神秘抽象图标让人猜。
- **感知稳定性（工具栏与菜单原地置灰保位置）**：菜单项、工具栏图标与右键命令在当前上下文暂不可用时，必须**原地置灰保留位置**（可附原因说明），不能凭空消失导致相邻图标左右跳位破坏肌肉记忆。
- **直接操作优先于间接填表**：能直接在对象上拖拽排序、拖边调宽、双击原地改名或框选多选的，不要逼用户点开编辑弹窗去填坐标数字或连点“上移/下移”按钮。
- **级联悬停子菜单防滑丢**：多级悬停子菜单必须提供斜向移动安全区容错（Safe Triangle）或改为点击展开，防止鼠标从父项斜划向子菜单时途径相邻项把菜单瞬间关掉。

## 5. 控件与选项量级选型（必须）

- **≤ 4 项互斥短选项**：优先平铺单选或分段控件一目了然，不藏进下拉菜单增加一次点击与隐藏负担；超过 6 项单选改用可搜索下拉。
- **Switch vs Checkbox**：立即生效的布尔开关用 Switch（不配额外保存按钮）；随表单提交或列表批量勾选的用 Checkbox；纯布尔值不用下拉框。
- **Button vs Link / Tabs**：原地触发状态变更用 Button，跨路由或打开外部文档用 Link；互不依赖的分类用 Tabs，需要横向并排对照的数据不能拆进不同 Tab。

## 6. 表单与输入人因铁律（必须）

- **宽进严出 + 失败不清空输入**：输入校验必须自动清洗常见无害格式（自动去首尾空格、容错手机号/卡号/API Key 中的空格或短横线）；提交失败时**严禁清空用户已填写的内容**（重复重填是最高频的挫败源）。
- **晚惩罚、早奖励（Reward Early, Punish Late）**：用户正在输入空字段时不能每敲一个字符就飙红报错（首次失焦 `onBlur` 或点提交时再报错）；一旦用户回头修改满足规则，在输入中（`onChange`）**立刻消除报错并正向确认**。
- **拒绝“哑巴禁用提交按钮”**：不要把提交按钮静默置灰却不告诉用户缺了什么；优先保持可点，点击时就地高亮报错并自动滚动聚焦第一个错误项；若确需禁用，必须在按钮旁直接写明前置缺项。
- **持久 Label + 外露规则**：Placeholder 一打字就会消失，不能拿 Placeholder 替代持久可见的 Label，也不能在 Placeholder 里塞长规则说明；完成录入所需的校验规则与前置条件必须常驻外露在字段旁或下方，**禁止藏在悬浮 Tooltip 里**。
- **微交互底线**：不能拦截或屏蔽用户粘贴（禁止阻止 `paste`）；复选框/单选框的 Label 与控件合并为单一点击热区不留死区；含未保存修改离开页面时提供防丢拦截；邮箱、验证码、用户名、API Key 关闭拼写检查（`spellCheck=false`）；打开搜索或表单弹窗时自动聚焦首个输入项。

## 7. 可访问性横切底线（必须）

相关控件必须覆盖：语义原生元素优先（`<button>` / `<a>` / `<label>`，不用 `<div onClick>` 冒充按钮）、完整键盘操作与焦点归还、清晰的 `:focus-visible`（禁止无替代移除焦点框）、非颜色单一通道（红绿状态叠图标或文字）、纯图标按钮配 `aria-label`、装饰图标标 `aria-hidden="true"`、异步 Toast 与校验提示配 `aria-live="polite"`、Flex 截断文本子项配 `min-w-0` 防省略号失效。
