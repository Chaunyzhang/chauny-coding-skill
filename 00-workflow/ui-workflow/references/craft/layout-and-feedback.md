# 布局稳定性、空态、耗时与反馈

定义页面结构、内容边界、状态组合、空态、加载与系统反馈时读。目标是在视觉前把布局物理与运行态反馈锁死，不让实现者临场猜或破坏既有骨架。

## 目录

- 1. 内容结构、层级与多维状态
- 2. 布局防挤压与物理稳定性（必须）
- 3. 三档耗时反馈与等待心理（必须）
- 4. 反馈空间落点与无模式优先（必须）
- 5. 四类空态细分、零态结构保底与诚实报错（必须）
- 6. 消除界面杂税、状态记忆与导航保现场（必须）

## 1. 先定结构骨架，再填内容（Structure-Before-Content，必须）

面对复杂需求，**严禁先把所有信息一股脑铺上屏再去“调间距/藏边框”**（信息一旦直接堆满界面，结构主次会被瞬间淹没，后续只能打补丁而改不动骨架）。必须按三步倒推推进：

1. **步骤 A — 信息盘点与三桶分流（只盘点、不上屏）**：
   - 收集全部待呈现的字段、集合、状态与动作，逐项标注 `required/optional`、数量与长度极值（零值/常规/极大）及溢出规则（不能围绕一条工整假数据设计）；
   - 按五层层级（Task → Object → Action → Information → Visual，视觉不能反过来发明产品层级）把全部信息强制分进三桶：
     - **Primary（首屏主路径）**：用户当前一步必须直视与操作的核心对象和主动作；
     - **Secondary（随主对象退后）**：附着在主对象上的辅助元信息，视觉主动降噪；
     - **Deferred（延迟/按需收起）**：禁止平铺在默认首屏，明确指定其收口去处（详情抽屉、Inspector、Popover、折叠区、次级设置或点击触发）。
2. **步骤 B — 先画无内容的抽象结构骨架与槽位预演（Skeleton & Slot Capacity Proof）**：
   - 在摆放任何一条具体文案或组件皮肤之前，先用 `Flow → Surface/Screen → Region（独立布局 ownership）→ Section（语义组）→ Pattern → Component` 画出**抽象结构骨架树**；
   - 为每个 Region 与槽位写死四项契约：**唯一职责**、**滚动归属**、**容量上限（最多几项 / 几行 / 多长）**、以及**内容灌入预演**（明确推演 0 条、常规、超长文本、高数量与缺配态放进这个槽位后会呈现什么形态，证明不会变形或挤压邻居）。
3. **步骤 C — 按槽灌入与“无槽停手”纪律**：
   - 骨架与容量预演通过后，才把三桶信息严格按槽位与容量上限填进去；
   - 遇到原骨架里没有合法槽位的新信息（如临时新增的提醒条、统计项或开关），**严禁顺手往旁边硬塞一行或插一个新块**，必须回到步骤 B 重新审视结构（合并、替换、降级进 Deferred，或正式重构骨架）。

- **状态是多维组合，不是单一枚举**：Domain、Data（loading/loaded/empty/stale/partial/error）、Operation（idle/submitting/failed/retrying）、Permission、Environment（online/offline/reconnecting）、Interaction 与 Selection 可同时成立（如 `completed + offline + syncPending + focused`）。每个重要状态写清 source、owner、entry/exit、可见表现、允许动作与恢复路径。

## 2. 布局防挤压与物理稳定性（必须）

- **禁止条件性文字条挤压原结构（No Structural-Squeeze Notice）**：任何因状态或前置条件缺失而出现的提醒文字（如未配置 API Key、缺权限、待登录、额度提示、说明条），无论是否有边框，**都不能靠临时插进已有文档流把主画布顶矮、把工具栏/输入区压扁或破坏同排顶底对齐**（临时插入会制造布局跳动并破坏原有视觉秩序）。必须按阻塞程度三选一落位：
  1. **整块功能区因缺配不可用**（如整个对话面板未配密钥）：原地占用该区域原本的 Empty / Setup 空态空间替换内容，不叠在正常界面上方往下挤；
  2. **主界面仍可用，仅某项功能缺配置**：走**按需触发**（用户点击该功能或发送时弹出轻量配置 Popover/抽屉），或只占用工具栏/设置入口**原本预留好的极简状态点/徽章**，不能平时常驻插一行提醒文字挤占版面；
  3. **极少数真·全局阻断告警**（如全站断网、账号封禁）：走**不占文档流的浮层/角落浮条**，或在 Spec 阶段就划定独立固定槽位，不能临时撑高顶栏或某个分栏。
- **结构先定，内容迁就结构**：并排面板、同排卡片和主结构框必须由外框架锁定统一尺寸并对齐顶底边（头部固定，内部列表独立滚动、截断或留白）；不能用 `items-start` 或任由内容条目增减把同排模块撑得一高一矮（框体随数据变形会破坏整页秩序与扫描轴）。
- **交互态零几何回流（Anti-Reflow）**：`hover / active / selected / focus` 不能通过切换 `font-weight`（如 400 变 600）或动态增减边框厚度来表达（字宽或盒尺寸变化会推动相邻按钮和导航横向抖动）；改用颜色、背景微抬升、`box-shadow` 或占位 `outline`。
- **异步内容与媒体锁定占位尺寸（防 CLS 误点）**：图片、头像、异步卡片与动态模块加载前必须预留确定宽高比（`aspect-ratio`）或最小高度（`min-height`），不能加载完后突然把用户 400ms 内正准备点击的按钮顶跑（突发位偏移极易诱发误点）。
- **滚动隔离与吸顶遮挡保护**：侧栏、弹窗、抽屉等独立滚动区必须隔离滚动链（`overscroll-behavior: contain`），防止滚到底部时带动底层主页面一起滚动；页内锚点跳转与键盘 Tab 聚焦项必须预留顶部偏移（`scroll-margin-top`），不能被吸顶导航或底栏盖住当前焦点元素。

## 3. 三档耗时反馈与等待心理（必须）

按真实响应时间选反馈形态，不拿单一转圈应付所有等待：
- **`< 100–300ms`（瞬时响应区）**：不显示 Spinner 或骨架屏。凡触发加载态必须加 **150–300ms 显示延迟**；一旦显示则至少保持 **300–500ms** 再退出（快网下 loading 一闪而过会制造页面闪烁感，反而显得卡顿）。
- **`300ms–10s`（等待保持心流区）**：使用局部/按钮内 Loading，或**严格对齐终态真实几何尺寸**的骨架屏（不用失真固定假高度骨架屏，高度高度动态区域改用局部加载指示）。
- **`> 10s`（长耗时任务区）**：必须给出确定进度百分比或清晰阶段步骤，并提供**取消或后台继续**出口（不锁死页面让用户盲等）。
- **乐观更新 vs 悲观锁定**：低风险高频动作（收藏、开关、重命名、轻标记）优先乐观更新并在失败时清晰回滚报错；涉及资金、删除、权限或不可逆外部写入必须悲观锁定防重入。

## 4. 反馈空间落点与无模式优先（必须）

先回答“现在什么状态 / 是否进行中 / 成败 / 危险后果 / 如何恢复”，再决定反馈形式：
- **非阻塞系统提醒**（崩溃恢复、撤销重做、后台完成、保存成功）：必须走角落悬浮 Toast（桌面/Web 惯例右下角，不挤压主画布）；带决策动作的 Toast（如恢复工程）保持驻留不自动消失。
- **富无模式反馈（Rich Modeless Feedback）**：保存态、字数、同步状态、轻校验、连接状态优先在原工作区内用就地视觉微信号（状态灯、标题栏未保存圆点、行内轻标注）呈现，不弹必须点“知道了”的阻塞框打断心流。
- **无模式优先与防模式错误**：用户的注意力焦点只有一个，能不锁模式就不锁模式；若必须进入特殊模式（批量多选、裁剪、录制、编辑态），必须在主视口给出无法忽略的视觉区分并提供 `Esc` 或显式退出按钮，防止用户按常态习惯敲快捷键触发误操作。
- **表单字段报错**：必须就近显示在对应字段下方并在提交失败时聚焦首个错误项，不用全局弹窗打断录入。

## 5. 四类空态细分、零态结构保底与诚实报错（必须）

- **结构底子与数据内容解耦（Structure Persists Under Zero Data，必须）**：仪表盘、热力图、时间点阵、趋势图、流向图与结构化统计视图在零数据或未启用采集态下，**必须保留完整的零态结构骨架底子**（如完整周期的零态空格方块、时间矩阵空点阵、坐标轴与零基线、表头与已知实体的零值行），仅在结构底子之上附着轻量浮层提示或在预留状态位提供一键开启/采集入口；**严禁**因无数据就把整块可视化结构直接销毁，塌成大片空白黑洞配一句孤零零的「暂无数据」（结构本身承载页面认知与空间秩序，抹掉底子会让用户看不懂此页用途并制造压迫死空）。
- **空态必须分 4 类，不能统统写“暂无数据”**（不同空态用户的下一步完全不同）：
  1. **首次零数据**：一句人话说明此区用途 + 1 个主行动按钮（不堆说教墙）；
  2. **搜索/筛选无结果**：明确告知是当前条件过滤导致 + **一键清空筛选**按钮；
  3. **全部处理完（清零态）**：平静确认已清空，不强行塞大按钮制造压力；
  4. **加载失败/断网空态**：写明失败原因 + 直接可点的重试按钮。
- **报错三要素**：每条面向用户的错误提示必须包含**具体出问题的对象 + 可读原因 + 下一步可执行动作**，禁止输出「操作失败 / 发生未知错误 / Oops」这类无信息废话。

## 6. 消除界面杂税、状态记忆与导航保现场（必须）

- **消除界面杂税**：凡不直接推进用户目标的额外中转步骤（改完轻偏好还需额外点“保存”、弹“操作成功”逼人点关闭、常用高频项藏 3 层菜单）必须裁掉或自动化。
- **记住用户现场（Track State）与安全默认值**：窗口尺寸位置、分栏拖拽宽度、侧栏折叠态、列表排序筛选、最近选中页签与未发送草稿，重开或切回必须自动恢复；绝大多数用户不改设置，出厂默认值必须就是最安全、最体面的选择。
- **导航回退保现场**：从详情页返回列表必须还原原滚动位置与筛选条件；Web 应用将筛选、页签与分页状态同步到 URL 查询参数，并使用原生链接语义支持新标签页打开。
